# Fatucci — бот заказа завтраков в апартаменты

Гость сканирует QR-код в апартаментах, за минуту оформляет завтрак и платит картой
прямо в чате. Менеджер ведёт всё из админ-панели внутри Telegram — без сайта, без
таблиц и лишних сервисов.

Код рассчитан на два мессенджера — **Telegram** и **MAX**: бизнес-логика написана один
раз, каналы подключаются адаптерами. Сейчас бот работает в Telegram; адаптер MAX лежит
готовым и включается токеном в админке, когда он понадобится.

---

## 1. Что умеет

**Гость**
- Сканирует QR-код своего дома → бот сам знает объект, адрес и цену.
  По общему QR (реклама, визитки) гость просто пишет адрес — бот сам находит дом
  в списке объектов, а незнакомый адрес честно помечает «менеджер проверит».
- Отмечает **сразу несколько дат** — например, все дни проживания. Заказ остаётся
  одним, с одним номером, но по каждому дню виден свой набор и своя доставка.
- Выбирает количество наборов, вводит номер апартаментов, делится телефоном кнопкой.
- Пишет про **аллергии и непереносимости** — они видны и менеджеру, и на кухне.
- Проверяет карточку заказа с разбивкой по датам и подтверждает.
- Получает статусы прямо в чат: принят в работу → счёт на оплату → оплачен → доставлен.
- Может отменить **весь заказ или один день** и подтвердить получение.
- Видит состав сетов, **условия заказа**, доставку, частые вопросы и свои заказы.
- Кнопка **🆘 Поддержка** закреплена под полем ввода: контакты техподдержки в один тап,
  в любой момент — даже посреди оформления заказа, черновик при этом не сбивается.
- После заказа видит блок «Ещё от Fatucci» (Fine Food, Дольче Дача, кейтеринг).

**Менеджер**
- Все заказы падают в общий рабочий чат карточкой с кнопками: принять / отклонить / написать гостю.
  Многодневный заказ — одна карточка, а не пачка сообщений.
- Подтверждение, оплата и отказ применяются ко всему заказу; доставку и отмену
  можно отмечать по каждому дню отдельно.
- Смена статуса автоматически уведомляет гостя.
- Ежедневная сводка для курьеров — одно готовое сообщение, которое можно скопировать целиком.
- Ежедневное напоминание гостям «успейте заказать завтрак на завтра» — по расписанию,
  без ручной рассылки.

**Админ-панель (`/admin` в Telegram)**

Собрана в шесть разделов, чтобы не теряться:

| Раздел | Что внутри |
|---|---|
| 📦 Заказы | Фильтры, поиск, карточка, история статусов |
| 🥐 Меню и цены | Сеты, ротация по дням, скидки за количество, доп. предложения |
| 🏢 Объекты и QR | Дома, адреса, цены, генерация QR-кодов |
| 🚚 Курьерам | Сводка по форме курьерской службы, время и шаблон |
| 📊 Отчёты | Статистика по объектам и QR, выгрузка в CSV, гости и чёрный список |
| ⚙️ Настройки | Общие, каналы, оплата, тексты, доступ, напоминания, проверка базы |

Под полем ввода закреплена постоянная кнопка: у администратора — **🛠 Админ-панель**
(команду `/admin` набирать не нужно), у гостя — **🆘 Поддержка**. Кому что показывать,
бот решает сам; кнопка возвращается на место после запроса телефона и других шагов,
где клавиатура временно подменяется.

Контакт техподдержки задаётся в `⚙️ Настройки → Общие → Контакт техподдержки`
(по умолчанию `@marina_fatucci`). Если это `@username`, гость дополнительно получает
кнопку-ссылку «Написать в поддержку»; телефон или ссылка подставляются как есть.

**🗄 Проверка базы данных** (`⚙️ Настройки`) показывает, есть ли связь с базой,
как быстро она отвечает, сколько занимает места и что в ней лежит. Первое, что
стоит нажать, если бот повёл себя странно.

**❓ Справка — встроенный гайд.** Отдельный раздел с пояснением по каждому пункту
панели: что он делает, как им пользоваться и на что обратить внимание.
Начинается с пошаговой инструкции «С чего начать». Кнопка «❓ Как это работает»
есть и внутри сложных разделов.

## 2. Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить токены
python main.py
```

Проверка, что всё живо (ничего никуда не отправляет, работает на временной базе):

```bash
python selftest.py       # на локальном SQLite
python selftest_pg.py    # тот же набор на реальном PostgreSQL
```

`selftest_pg.py` создаёт в базе временную схему и удаляет её в конце —
боевые таблицы не трогаются, запускать безопасно даже на рабочей базе.

## 3. Заполнение `.env`

| Параметр | Что это | Обязателен |
|---|---|---|
| `TELEGRAM_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) | **да, и только он** |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@`. Не задано — бот определит сам | нет |
| `ADMIN_IDS` | Аварийный доступ к админке | нет, см. ниже |
| `ORDERS_CHAT_ID` | Рабочий чат для заказов | нет, задаётся в `/admin` |
| `MAX_TOKEN`, `MAX_BOT_USERNAME` | Бот в MAX | нет, задаётся в `/admin` |
| `PAYMENT_PROVIDER_TOKEN` | Токен кассы от @BotFather | нет, задаётся в `/admin` |
| `FATUCCI_DATABASE_URL` | Перебивает адрес базы, зашитый в коде | нет |
| `TZ_OFFSET` | Часовой пояс, `3` = Москва/Сочи | нет, по умолчанию 3 |

Для запуска достаточно **одного** `TELEGRAM_TOKEN` — всё остальное настраивается
кнопками внутри бота.

### Кто становится администратором

**Первый, кто написал боту, автоматически становится владельцем.** Ему приходит
сообщение об этом и кнопка в админ-панель. Дальше он добавляет менеджеров сам:
`/admin → 👑 Доступ → Добавить`, по числовому ID или выбором из тех, кто уже писал боту.

- Владельца нельзя убрать из панели — защита от потери доступа к боту.
- `ADMIN_IDS` в окружении задавать не нужно. Это запасной вход: если владелец
  потерял доступ, впишите туда свой ID и перезапустите бота.
- Если `ADMIN_IDS` задан, автоназначение владельца не срабатывает.

Так что порядок запуска на новом хостинге простой: задали токен → запустили →
написали боту `/start` → вы владелец.

**Как узнать свой ID и ID чата:** напишите боту (или добавьте его в рабочий чат) команду `/id` —
бот ответит обоими числами. ID группы всегда с минусом, например `-1001234567890`.

### Переменные окружения вместо `.env`

Файл `.env` **необязателен**. Если хостинг умеет задавать переменные окружения
(панель bothost, docker, systemd) — задайте их там, файл не нужен вовсе.
Приоритет такой: **переменные окружения → `.env` → значения по умолчанию**,
поэтому переменной всегда можно перебить то, что лежит в файле.

Поддерживаются альтернативные имена — берётся первое непустое:

| Основное имя | Синонимы |
|---|---|
| `TELEGRAM_TOKEN` | `BOT_TOKEN`, `TG_TOKEN` |
| `TELEGRAM_BOT_USERNAME` | `BOT_USERNAME` |
| `MAX_TOKEN` | `MAX_BOT_TOKEN` |
| `MAX_BOT_USERNAME` | `MAX_USERNAME` |
| `ADMIN_IDS` | `ADMIN_ID`, `ADMINS` |
| `ORDERS_CHAT_ID` | `ORDERS_CHAT` |
| `PAYMENT_PROVIDER_TOKEN` | `PROVIDER_TOKEN`, `PAYMASTER_TOKEN` |
| `DATABASE_URL` | `POSTGRES_URL`, `POSTGRESQL_URL`, `DB_URL` |

Кавычки и пробелы вокруг значений срезаются автоматически — если панель хостинга
сохранила токен как `"123:ABC"`, это не сломает запуск.

При старте бот пишет в лог, что именно нашёл и из какой переменной (токены — замаскированные):

```
Файл .env: нет. Переменные окружения имеют приоритет.
Telegram-токен: 123456…Dsaw (из BOT_TOKEN)
MAX-токен: не задан
Админы: [123456789]
```

Если токена нет, бот сообщает об этом и **сразу завершается** — не висит молча.

### Telegram-бот
1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. `/setprivacy` → **Disable** — иначе бот не увидит команды в рабочем чате.
3. Добавить бота в рабочий чат менеджеров и дать право писать сообщения.

### MAX-бот — подключается без перезапуска

1. В MAX открыть **MasterBot**, создать бота, получить токен.
2. В боте: `/admin → 📱 Каналы` → вставить **токен** и **username**.
3. Всё. Бот поднимет MAX сам в течение минуты — перезапускать не нужно.

Там же MAX можно временно выключить переключателем, не удаляя токен.
Пока токен не введён, бот работает только в Telegram — это ровно тот сценарий
«сначала Telegram, MAX позже», который обсуждался с заказчиком.

Смена токена подхватывается на лету: супервизор видит новое значение и
перезапускает канал сам.

## 4. Размещение на bothost

Бот не требует открытых портов и белого IP: long polling для обоих мессенджеров,
оплата — встроенными платежами Telegram.

1. Загрузить папку проекта целиком (или подключить репозиторий).
2. Главный файл — `main.py`, зависимости — `requirements.txt`.
3. В конструкторе задать одну переменную окружения — **`TELEGRAM_TOKEN`**
   (подойдёт и `BOT_TOKEN`). Адрес базы уже зашит в коде, см. ниже.
4. Запустить, написать боту `/start` — вы станете владельцем и получите доступ к `/admin`.

Файл `.env` не нужен; в репозитории его нет намеренно — он в `.gitignore`,
чтобы токены и пароль базы не попадали в git.

### Адрес базы зашит в код

Переменная окружения на хостинге оказалась ненадёжной — значение доезжало
искажённым, и бот не мог подключиться. Поэтому строка подключения лежит
в `app/dsn.py` и работает без всякой настройки на сервере.

Порядок выбора адреса:

1. `FATUCCI_DATABASE_URL` — если задана, побеждает всё остальное;
2. зашитая строка в `app/dsn.py` — обычный рабочий вариант;
3. `DATABASE_URL` — запасной путь, если зашитой строки нет.

Особое значение `FATUCCI_DATABASE_URL=sqlite` переключает бота на локальный
файл — этим пользуются тесты, чтобы случайно не попасть в боевую базу.

**Сменить базу:**

```bash
python -m app.dsn "postgresql://пользователь:пароль@хост:порт/база"
```

Команда напечатает готовый блок — вставьте его в `app/dsn.py` вместо старого.

⚠️ Строка свёрнута, а не зашифрована: она не попадётся роботам, которые
сканируют публичные репозитории в поисках паролей от баз, но человек,
открывший файл, развернёт её за минуту. Если репозиторий открыт, пароль
базы стоит считать известным.

### Всё состояние — в базе

В PostgreSQL хранится **всё**: заказы, объекты, меню, ротация, цены и скидки,
тексты, настройки, администраторы, незавершённые заказы гостей, фотографии сетов
и кэш вложений. На диск при работе с PostgreSQL не пишется ничего — папка
проекта может быть хоть только для чтения, а переезд между хостингами
не теряет данные.

**Бэкап** — обычный дамп:

```bash
pg_dump "$DATABASE_URL" > fatucci.sql      # сохранить
psql "$DATABASE_URL" < fatucci.sql         # восстановить
```

### Без PostgreSQL тоже работает

Если `DATABASE_URL` не задан, бот использует файл SQLite (`data/bot.db`) —
удобно для локальной разработки. Схема и весь код одинаковые: движок выбирается
одной переменной, переписывать ничего не нужно.

## 5. Первые шаги после запуска

0. Написать боту `/start` — первый написавший становится владельцем.
1. `/admin` → `⚙️ Настройки → Общие` → указать **чат для заказов** (`/id` в этом чате).
2. `🏢 Объекты` → удалить демо-объект, добавить свои (название → адрес → цена).
3. `🥐 Меню и сеты` → создать сеты, загрузить фото, задать состав.
4. `🗓 Ротация` → назначить сет на каждый день недели.
5. `🔗 QR-коды` → выбрать объект → бот пришлёт PNG для печати и ссылки.
6. `💳 Оплата` → вставить токен кассы от @BotFather → `🧪 Проверить оплату`.
   **Без этого шага гости не смогут оформить заказ** — бот честно скажет, что приём
   заказов пока недоступен.
7. `🚚 Курьерам` → время автоформирования и шаблон сообщения.
8. `✍️ Тексты` → отредактировать приветствие, FAQ, доставку под себя.
9. `👑 Доступ` → добавить менеджеров.
9.1 `⚙️ Настройки → Общие` → проверить **контакт техподдержки** (кнопка 🆘 у гостей).
10. `📱 Каналы` → подключить MAX, когда понадобится второй мессенджер.

Всё то же самое, но подробнее — в самом боте: `/admin → ❓ Справка → 🚀 С чего начать`.

## 6. Как устроены объекты и QR

Иерархия из ТЗ: **сеть → дом → квартира**.

- **Объект = дом** (свой адрес, своя цена, свой QR-код).
- Поле «Сеть / группа» — для отчётов по сети целиком (например, «Альфа-Апартаменты»).
- Квартиры отдельными объектами не заводятся: гость вписывает только номер апартаментов.
- **Общий QR** (галка «is_general» у демо-объекта `obshiy`) — для рекламы и тестов:
  гость сам выбирает объект из списка. Заказ всё равно помечается кодом этого QR,
  поэтому видно, сколько заказов пришло с рекламы.
- Отключённый объект = QR перестаёт работать, ссылка остаётся.
  Чтобы перепривязать QR к другому объекту — просто поменяйте у объекта поле «Код для QR».

Ссылки, которые зашиты в QR:
```
Telegram   https://t.me/<бот>?start=<код объекта>
MAX        https://max.ru/<бот>?start=<код объекта>
```

## 7. Статусы заказа

| Статус | Когда ставится | Что видит гость |
|---|---|---|
| 🆕 Не оплачен | заказ только что оформлен | «Заявка принята, ждём подтверждения» |
| 🔧 Принят в работу | менеджер нажал кнопку | сообщение + **счёт на оплату** |
| 💰 Оплачен | Telegram подтвердил платёж (или менеджер вручную) | «Оплачено, ждите доставку» |
| ❌ Отменён (день) | гость отменил одну дату многодневного заказа | остальные дни едут как обычно |
| 🚚 Доставлен | менеджер нажал кнопку | «Приятного аппетита» + кнопка «Я получил» |
| ✅ Получен | гость подтвердил | благодарность |
| ⛔ Отклонён | менеджер отклонил (с причиной) | причина + контакт менеджера |
| ❌ Отменён | гость отменил сам | подтверждение отмены |

## 8. Цены и скидки

**Цена завтрака задаётся у объекта** — так в разных апартаментах она разная.
Если у сета указана своя цена, она перебивает цену объекта.

**Скидка за количество** (`🥐 Меню и цены → 💰 Скидки`) — чем больше наборов
гость берёт **на один день**, тем дешевле каждый. Накопительно за всё проживание
скидка не считается, только внутри одного заказа — как и просил заказчик.

Формат настройки:

```
3=5, 5=10, 10=15
```

читается как «от 3 наборов −5%, от 5 наборов −10%, от 10 наборов −15%».

Проценты, а не рубли — потому что цена у объектов разная: настроили один раз,
работает везде. В админке рядом показывается табличка «сколько — почём»
на примере реального объекта, чтобы не считать в уме.

Гость видит скидку сразу: на кнопках выбора количества (`3 · −5%`) и отдельной
строкой в карточке заказа.

## 9. Оплата — счёт прямо в чате

Оплата идёт **встроенными платежами Telegram**: бот присылает гостю счёт в чат,
тот платит картой в пару касаний, и статус заказа обновляется автоматически.
Ни ссылок, ни переходов на сторонние сайты, ни вебхуков и белого IP.

**Пока касса не подключена, бот не даёт оформить заказ** — гость видит сообщение,
что приём заказов временно недоступен, и кнопку «Написать менеджеру». Так не
появляется заказов, за которые нечем заплатить. В админ-панели при этом висит
предупреждение «💳 Касса не подключена».

### Подключение

1. **@BotFather** → `/mybots` → ваш бот → **Payments** → выбрать кассу
   (ЮKassa, PayMaster, Т-Банк — что удобнее) и пройти привязку.
2. BotFather выдаст токен вида `123456789:TEST:abcdef…`
3. В боте: `/admin` → `⚙️ Настройки` → `💳 Оплата` → вставить токен.
4. Нажать **«🧪 Проверить оплату»** — бот скажет, принят ли токен и в каком режиме.

Менять кассу можно когда угодно: код ни к одному провайдеру не привязан,
меняется только токен в админке.

### Тестовый и боевой режим

Режим зашит в сам токен:

| В токене | Что значит |
|---|---|
| `:TEST:` | Деньги не списываются. Тестовая карта `4111 1111 1111 1111`, срок — любой будущий, CVC любой. |
| `:LIVE:` | Настоящие платежи. |

⚠️ Важная особенность тестового режима: Telegram доставляет счёт **только тем, кто
во взаимных контактах у владельца бота**. Если счёт «не приходит» при тестировании —
дело в этом, а не в коде. Добавьте тестировщика в контакты.

### Как это работает внутри

1. Менеджер жмёт «Принять в работу» → бот отправляет гостю один счёт на весь заказ
   (`sendInvoice`), с разбивкой по датам в описании.
2. Telegram спрашивает бота, всё ли в порядке (`pre_checkout_query`) — бот отвечает «да».
3. После оплаты приходит `successful_payment` → **все дни заказа** становятся оплаченными,
   гостю уходит подтверждение, карточка у менеджеров обновляется.

Ничего опрашивать не нужно — Telegram сам сообщает об оплате.

Если счёт по какой-то причине выставить не удалось, гость получает сообщение
«менеджер свяжется с вами», а менеджеры — предупреждение в рабочий чат: заказ
не теряется.

### Отмена и возврат

Отменить заказ гость может до времени из настройки **«Отмена до»**
(`⚙️ Настройки → Общие`, по умолчанию `18:30` накануне дня доставки). Позже —
бот всё равно отменит доставку, но честно предупредит, что оплата за ближайший
день не возвращается. Возврат денег делается на стороне кассы.

### Чек по 54-ФЗ

Если касса требует передавать чек, JSON для него вписывается в поле
`Доп. данные провайдера (JSON)` в том же разделе — бот передаст его как есть
в `provider_data`.

## 10. Выгрузка для курьеров

Собирается **одним готовым сообщением** — как просил заказчик, не таблицей и не пачкой сообщений.

- Автоматически в заданное время (`/admin → 🚚 Курьерам`), на завтрашний день.
- Вручную — на любую дату, кнопкой.
- Кнопка **«📋 Текстом для копирования»** присылает ту же сводку моноширинным блоком:
  в Telegram он копируется одним касанием.
- Попадают только заказы в статусах из настройки `courier_statuses`
  (по умолчанию «принят в работу» и «оплачен»), отменённые и отклонённые исключены.

### Форма сообщения

По умолчанию шаблон повторяет форму курьерской службы, которую прислал заказчик:

```
📥 Откуда: Fatucci fine food, Фабрициуса 58/2, павильон 26
📍 Адрес: г. Сочи, ул. Северная, д. 12, апарт. 45
👥 Получатель: +7 (999) 123-45-67, Иван Петров
⏰ Когда: 08:00
🥐 Заказ: Сет Б · Сытный × 3
✏️ Комментарий: отчитаться о доставке · позвонить за 10 минут
Доставка:
```

Поля **«Откуда»**, **«Когда забирать»** и **«Комментарий»** меняются в
`⚙️ Настройки → 🚚 Выгрузка курьерам` — лезть в шаблон для этого не нужно.

Строка «🥐 Заказ» добавлена сверх формы: курьеру полезно знать, сколько пакетов.
Если курьерская служба лишних строк не хочет — удалите её из шаблона.

Имя получателя берётся из карточки контакта, которой гость делится при заказе.

Сам шаблон правится в `/admin → ⚙️ Настройки → 📋 Шаблон выгрузки`.
Доступные подстановки:

```
Шапка/подвал:  {date_h} {date} {orders_count} {sets_count} {total} {now}
Строка заказа: {from} {address} {apartment} {name} {phone} {pickup}
               {set_title} {qty} {note} {comment} {number} {total}
```

Когда Fatucci пришлёт финальную форму курьерской службы — её достаточно вбить
в эти четыре поля, код трогать не нужно.

## 11. Сертификаты и доступ к API (важно)

Внешние адреса, с которыми работает бот, подписаны разными удостоверяющими центрами —
и с одним из них бывают проблемы:

| Адрес | Кем подписан | Что с этим |
|---|---|---|
| `platform-api2.max.ru` (MAX) | **НУЦ Минцифры** (Russian Trusted Root CA) | Корня нет ни в Windows, ни в большинстве сборок Linux, ни в certifi |
| `api.telegram.org` | Let's Encrypt | С сертификатом всё в порядке |

Это решено внутри проекта, ничего настраивать не нужно:

- корневые сертификаты Минцифры лежат в `app/certs/` и подключаются в `app/net.py`
  **только для соединений с MAX** — для Telegram доверие остаётся обычным;
- `certifi` подставляется всему процессу при старте (`net.apply_ca_bundle()`),
  иначе на Windows падает даже aiogram;
- проверка сертификатов нигде не отключается — мы только добавляем доверенные корни.

Сертификат `russian_trusted_sub_ca.cer` действует до марта 2027 года. Когда Минцифры
выпустит новый — достаточно положить свежий `.cer` в `app/certs/`, код подхватит любой
файл из этой папки.

### Если бот не видит Telegram с домашнего компьютера

`api.telegram.org` у многих российских провайдеров недоступен — бот будет писать
«Telegram: связь потеряна». На хостинге это обычно не проблема, а локально нужен
VPN или прокси. Проверить доступность:

```bash
python -c "import socket; socket.create_connection(('api.telegram.org', 443), timeout=10); print('доступен')"
```

Ошибка MAX при этом выглядит иначе (`SSLCertVerificationError`), так что
по тексту в логе всегда видно, это блокировка или сертификаты.

## 12. Структура проекта

```
main.py                 запуск: Telegram + MAX + фоновые задачи
selftest.py             самопроверка всего сценария без мессенджеров
app/
  config.py             чтение .env
  db.py                 хранилище: PostgreSQL или SQLite, схема, миграции
  defaults.py           тексты и настройки «из коробки»
  repo.py               весь SQL
  statuses.py           статусы заказа
  availability.py       доступные даты: дни доставки, отсечка, ротация
  flow.py               сценарий гостя — общий для обоих мессенджеров
  admin.py              админ-панель
  router.py             распределение событий: админка или гость
  notify.py             карточки заказов и уведомления
  orders_service.py     смена статусов и всё, что за ней следует
  payments.py           оплата: счёт через встроенные платежи Telegram
  pricing.py            цены и скидки за количество
  guide.py              тексты встроенной справки по админке
  media.py              картинки (хранятся в базе, не на диске)
  dsn.py                адрес базы, зашитый в код
  courier.py            сводка для курьеров
  scheduler.py          фоновые задачи
  qrgen.py              генерация QR
  channels/
    base.py             общий контракт канала
    telegram.py         адаптер Telegram (aiogram 3)
    max.py              адаптер MAX (Bot API)
selftest_pg.py          тот же набор проверок на реальном PostgreSQL
data/                   файл SQLite, если PostgreSQL не используется
```

**Как добавить третий мессенджер:** написать ещё один адаптер в `app/channels/`
по контракту `base.Channel` — сценарий и админка менять не нужно.

## 13. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Заказы не приходят в чат | Бот не добавлен в чат или неверный `orders_chat_id`. Проверьте `/id` в чате. Если чат недоступен, бот сам пришлёт заказ в личку админам и напишет предупреждение в лог. |
| Бот не видит `/admin` | Ваш ID не в `ADMIN_IDS`. Узнать: `/id`. |
| Нет доступных дат | Все даты закрыты отсечкой, либо в ротации нет активного сета, либо у объекта не заданы дни доставки. |
| QR не генерируется | Не заданы `TELEGRAM_BOT_USERNAME` / `MAX_BOT_USERNAME`. |
| MAX молчит | Пустой `MAX_TOKEN`, либо выключен тумблер в `⚙️ Настройки → 📱 Каналы`. Ошибки авторизации видны в логе при старте. |
| Счёт не приходит гостю | В тестовом режиме Telegram шлёт счета только взаимным контактам владельца бота. Проверьте токен кнопкой `🧪 Проверить оплату`. |
| Фото сета не показывается | Файл в `data/photos/` удалён — загрузите заново; бот в этом случае просто отправит текст. |

Логи пишутся в стандартный вывод — на bothost они видны в консоли приложения.
Уровень подробности — `LOG_LEVEL=DEBUG` в `.env`.
