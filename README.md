# Fatucci — бот заказа завтраков в апартаменты

Один код — два мессенджера: **Telegram** и **MAX**. Заказы из обоих каналов попадают
в одну базу и в один рабочий чат менеджеров. Управление — из админ-панели прямо в Telegram,
без сайта и лишних сервисов.

---

## 1. Что умеет

**Гость**
- Сканирует QR-код своего дома → бот сам знает объект, адрес и цену.
- Выбирает дату доставки (бот показывает только реально доступные даты и сет этого дня).
- Выбирает количество наборов, вводит номер апартаментов, делится телефоном кнопкой.
- Проверяет карточку заказа и подтверждает.
- Получает статусы прямо в чат: принят в работу → ссылка на оплату → оплачен → доставлен.
- Может отменить заказ и подтвердить получение.
- Видит состав сетов, условия доставки, частые вопросы, свои заказы.
- После заказа видит блок «Ещё от Fatucci» (Fatucci Food, Дольче Дача и т. д.).

**Менеджер**
- Все заказы падают в общий рабочий чат карточкой с кнопками: принять / отклонить / написать гостю.
- Смена статуса автоматически уведомляет гостя.
- Ежедневная сводка для курьеров — одно готовое сообщение, которое можно скопировать целиком.

**Админ-панель (`/admin` в Telegram)**
- Заказы: фильтры, поиск, карточка, история статусов.
- Меню и сеты: название, состав, фото, цена, показать/скрыть.
- Ротация: какой сет в какой день недели + особые даты.
- Объекты: адрес, цена, дни доставки, время отсечки, мин/макс наборов.
- QR-коды: генерация PNG для Telegram и MAX, статистика заказов по каждому QR.
- Выгрузка курьерам: время, шаблон, ручная пересборка на любую дату.
- Оплата: ключи ЮKassa, проверка ключей, включение/выключение.
- Тексты бота — все до единого.
- Доп. предложения, гости и чёрный список, рассылка, статистика, выгрузка в CSV.

## 3. Заполнение `.env`

| Параметр | Что это | Обязателен |
|---|---|---|
| `TELEGRAM_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) | **да, и только он** |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@`. Не задано — бот определит сам | нет |
| `ADMIN_IDS` | Аварийный доступ к админке | нет, см. ниже |
| `ORDERS_CHAT_ID` | Рабочий чат для заказов | нет, задаётся в `/admin` |
| `MAX_TOKEN`, `MAX_BOT_USERNAME` | Бот в MAX | нет, задаётся в `/admin` |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Ключи ЮKassa | нет, задаются в `/admin` |
| `TZ_OFFSET` | Часовой пояс, `3` = Москва/Сочи | нет, по умолчанию 3 |

Для запуска достаточно **одного** `TELEGRAM_TOKEN` — всё остальное настраивается
кнопками внутри бота.

### Кто становится администратором

**Первый, кто написал боту, автоматически становится владельцем.** Ему приходит
сообщение об этом и кнопка в админ-панель. Дальше он добавляет менеджеров сам:
`/admin → 👑 Доступ → Добавить`, по числовому ID или выбором из тех, кто уже писал боту.

- Владельца нельзя убрать из панели — защита от потери доступа к боту.
- `ADMIN_IDS` в окружении задавать не нужно. Это запасной вход: если владелец
  потерял доступ, впишите туда свой ID и перезапустите бота.
- Если `ADMIN_IDS` задан, автоназначение владельца не срабатывает.

Так что порядок запуска на новом хостинге простой: задали токен → запустили →
написали боту `/start` → вы владелец.

**Как узнать свой ID и ID чата:** напишите боту (или добавьте его в рабочий чат) команду `/id` —
бот ответит обоими числами. ID группы всегда с минусом, например `-1001234567890`.

### Переменные окружения вместо `.env`

Файл `.env` **необязателен**. Если хостинг умеет задавать переменные окружения
(панель bothost, docker, systemd) — задайте их там, файл не нужен вовсе.
Приоритет такой: **переменные окружения → `.env` → значения по умолчанию**,
поэтому переменной всегда можно перебить то, что лежит в файле.

Поддерживаются альтернативные имена — берётся первое непустое:

| Основное имя | Синонимы |
|---|---|
| `TELEGRAM_TOKEN` | `BOT_TOKEN`, `TG_TOKEN` |
| `TELEGRAM_BOT_USERNAME` | `BOT_USERNAME` |
| `MAX_TOKEN` | `MAX_BOT_TOKEN` |
| `MAX_BOT_USERNAME` | `MAX_USERNAME` |
| `ADMIN_IDS` | `ADMIN_ID`, `ADMINS` |
| `ORDERS_CHAT_ID` | `ORDERS_CHAT` |
| `YOOKASSA_SHOP_ID` | `YK_SHOP_ID` |
| `YOOKASSA_SECRET_KEY` | `YK_SECRET_KEY` |

Кавычки и пробелы вокруг значений срезаются автоматически — если панель хостинга
сохранила токен как `"123:ABC"`, это не сломает запуск.

При старте бот пишет в лог, что именно нашёл и из какой переменной (токены — замаскированные):

```
Файл .env: нет. Переменные окружения имеют приоритет.
Telegram-токен: 123456…Dsaw (из BOT_TOKEN)
MAX-токен: не задан
Админы: [123456789]
```

Если токена нет, бот сообщает об этом и **сразу завершается** — не висит молча.

### Telegram-бот
1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. `/setprivacy` → **Disable** — иначе бот не увидит команды в рабочем чате.
3. Добавить бота в рабочий чат менеджеров и дать право писать сообщения.

### MAX-бот — подключается без перезапуска

1. В MAX открыть **MasterBot**, создать бота, получить токен.
2. В боте: `/admin → 📱 Каналы` → вставить **токен** и **username**.
3. Всё. Бот поднимет MAX сам в течение минуты — перезапускать не нужно.

Там же MAX можно временно выключить переключателем, не удаляя токен.
Пока токен не введён, бот работает только в Telegram — это ровно тот сценарий
«сначала Telegram, MAX позже», который обсуждался с заказчиком.

Смена токена подхватывается на лету: супервизор видит новое значение и
перезапускает канал сам.

## 4. Размещение на bothost

Бот рассчитан на файловое хранилище и не требует открытых портов и белого IP:
long polling для обоих мессенджеров, оплата проверяется опросом ЮKassa.

1. Загрузить папку проекта целиком.
2. Главный файл — `main.py`, зависимости — `requirements.txt`.
3. В конструкторе задать переменную окружения **`TELEGRAM_TOKEN`** (подойдёт и `BOT_TOKEN`) —
   больше ничего не требуется. Файл `.env` не нужен; в репозитории его нет намеренно,
   он в `.gitignore`, чтобы токены не попадали в git.
4. Запустить, написать боту `/start` — вы станете владельцем и получите доступ к `/admin`.
5. Папка `data/` создаётся сама: там база `bot.db`, фотографии и CSV-выгрузки.
   **Её нельзя чистить** — это все заказы и настройки.

**Бэкап:** достаточно скачать `data/bot.db` (и `data/photos/`). Восстановление — положить файл обратно.

## 5. Первые шаги после запуска

0. Написать боту `/start` — первый написавший становится владельцем.
1. `/admin` → `⚙️ Настройки → Общие` → указать **чат для заказов** (`/id` в этом чате).
2. `🏢 Объекты` → удалить демо-объект, добавить свои (название → адрес → цена).
3. `🥐 Меню и сеты` → создать сеты, загрузить фото, задать состав.
4. `🗓 Ротация` → назначить сет на каждый день недели.
5. `🔗 QR-коды` → выбрать объект → бот пришлёт PNG для печати и ссылки.
6. `💳 Оплата` → вписать ключи ЮKassa → `🧪 Проверить ЮKassa`.
7. `🚚 Курьерам` → время автоформирования и шаблон сообщения.
8. `✍️ Тексты` → отредактировать приветствие, FAQ, доставку под себя.
9. `👑 Доступ` → добавить менеджеров.
10. `📱 Каналы` → подключить MAX, когда будет готов бот в MAX.

## 6. Как устроены объекты и QR

Иерархия из ТЗ: **сеть → дом → квартира**.

- **Объект = дом** (свой адрес, своя цена, свой QR-код).
- Поле «Сеть / группа» — для отчётов по сети целиком (например, «Альфа-Апартаменты»).
- Квартиры отдельными объектами не заводятся: гость вписывает только номер апартаментов.
- **Общий QR** (галка «is_general» у демо-объекта `obshiy`) — для рекламы и тестов:
  гость сам выбирает объект из списка. Заказ всё равно помечается кодом этого QR,
  поэтому видно, сколько заказов пришло с рекламы.
- Отключённый объект = QR перестаёт работать, ссылка остаётся.
  Чтобы перепривязать QR к другому объекту — просто поменяйте у объекта поле «Код для QR».

Ссылки, которые зашиты в QR:
```
Telegram   https://t.me/<бот>?start=<код объекта>
MAX        https://max.ru/<бот>?start=<код объекта>
```

## 7. Статусы заказа

| Статус | Когда ставится | Что видит гость |
|---|---|---|
| 🆕 Не оплачен | заказ только что оформлен | «Заявка принята, ждём подтверждения» |
| 🔧 Принят в работу | менеджер нажал кнопку | сообщение + **кнопка оплаты** |
| 💰 Оплачен | ЮKassa подтвердила платёж (или менеджер вручную) | «Оплачено, ждите доставку» |
| 🚚 Доставлен | менеджер нажал кнопку | «Приятного аппетита» + кнопка «Я получил» |
| ✅ Получен | гость подтвердил | благодарность |
| ⛔ Отклонён | менеджер отклонил (с причиной) | причина + контакт менеджера |
| ❌ Отменён | гость отменил сам | подтверждение отмены |

## 8. Оплата

Используется **ЮKassa REST API**: гость получает ссылку на оплату — это работает
одинаково в Telegram и MAX (в MAX встроенных платежей нет вообще).

- Ключи вводятся в `/admin → 💳 Оплата`, правка кода не нужна.
- Кнопка `🧪 Проверить ЮKassa` сразу скажет, приняты ключи или нет.
- Статус платежа бот проверяет опросом каждые ~20 секунд — вебхук и домен не нужны.
- Если платёж не прошёл за `pay_timeout_min` (по умолчанию 3 часа), счёт очищается,
  и гость может запросить новую ссылку кнопкой «Оплатить» в разделе «Мои заказы».
- Чек по 54-ФЗ — переключатель `yk_receipt` (по умолчанию выключен; включать,
  если этого требует ваша схема налогообложения).
- Если ключи не заданы, гость получит сообщение «менеджер свяжется по оплате»,
  а менеджер — предупреждение в рабочий чат. Заказ при этом не теряется.

## 9. Выгрузка для курьеров

Собирается **одним готовым сообщением** — как просил заказчик, не таблицей и не пачкой сообщений.

- Автоматически в заданное время (`/admin → 🚚 Курьерам`), на завтрашний день.
- Вручную — на любую дату, кнопкой.
- Кнопка **«📋 Текстом для копирования»** присылает ту же сводку моноширинным блоком:
  в Telegram он копируется одним касанием.
- Попадают только заказы в статусах из настройки `courier_statuses`
  (по умолчанию «принят в работу» и «оплачен»), отменённые и отклонённые исключены.

Шаблон правится в `/admin → ⚙️ Настройки → 📋 Шаблон выгрузки`. Доступные подстановки:

```
Шапка/подвал:  {date_h} {date} {orders_count} {sets_count} {total} {now}
Блок объекта:  {address} {object_title} {orders_count} {sets_count}
Строка заказа: {apartment} {set_title} {qty} {phone} {comment} {number} {total}
```

Когда Fatucci пришлёт финальную форму курьерской службы — её достаточно вбить
в эти четыре поля, код трогать не нужно.

## 10. Сертификаты и доступ к API (важно)

Три внешних адреса, с которыми работает бот, подписаны разными удостоверяющими центрами —
и с двумя из них бывают проблемы:

| Адрес | Кем подписан | Что с этим |
|---|---|---|
| `platform-api2.max.ru` (MAX) | **НУЦ Минцифры** (Russian Trusted Root CA) | Корня нет ни в Windows, ни в большинстве сборок Linux, ни в certifi |
| `api.yookassa.ru` (оплата) | HARICA | Корня может не быть в хранилище Windows, но он есть в certifi |
| `api.telegram.org` | Let's Encrypt | С сертификатом всё в порядке |

Это решено внутри проекта, ничего настраивать не нужно:

- корневые сертификаты Минцифры лежат в `app/certs/` и подключаются в `app/net.py`
  **только для соединений с MAX** — для Telegram и ЮKassa доверие остаётся обычным;
- `certifi` подставляется всему процессу при старте (`net.apply_ca_bundle()`),
  иначе на Windows падает даже aiogram;
- проверка сертификатов нигде не отключается — мы только добавляем доверенные корни.

Сертификат `russian_trusted_sub_ca.cer` действует до марта 2027 года. Когда Минцифры
выпустит новый — достаточно положить свежий `.cer` в `app/certs/`, код подхватит любой
файл из этой папки.

### Если бот не видит Telegram с домашнего компьютера

`api.telegram.org` у многих российских провайдеров недоступен — бот будет писать
«Telegram: связь потеряна». На хостинге это обычно не проблема, а локально нужен
VPN или прокси. Проверить доступность:

```bash
python -c "import socket; socket.create_connection(('api.telegram.org', 443), timeout=10); print('доступен')"
```

Ошибки MAX и ЮKassa при этом выглядят иначе (`SSLCertVerificationError`), так что
по тексту в логе всегда видно, это блокировка или сертификаты.

## 11. Структура проекта

```
main.py                 запуск: Telegram + MAX + фоновые задачи
selftest.py             самопроверка всего сценария без мессенджеров
app/
  config.py             чтение .env
  db.py                 схема SQLite и первичное наполнение
  defaults.py           тексты и настройки «из коробки»
  repo.py               весь SQL
  statuses.py           статусы заказа
  availability.py       доступные даты: дни доставки, отсечка, ротация
  flow.py               сценарий гостя — общий для обоих мессенджеров
  admin.py              админ-панель
  router.py             распределение событий: админка или гость
  notify.py             карточки заказов и уведомления
  orders_service.py     смена статусов и всё, что за ней следует
  payments.py           ЮKassa
  courier.py            сводка для курьеров
  scheduler.py          фоновые задачи
  qrgen.py              генерация QR
  channels/
    base.py             общий контракт канала
    telegram.py         адаптер Telegram (aiogram 3)
    max.py              адаптер MAX (Bot API)
data/                   база, фото, выгрузки  ← бэкапить это
```

**Как добавить третий мессенджер:** написать ещё один адаптер в `app/channels/`
по контракту `base.Channel` — сценарий и админка менять не нужно.

## 12. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Заказы не приходят в чат | Бот не добавлен в чат или неверный `orders_chat_id`. Проверьте `/id` в чате. Если чат недоступен, бот сам пришлёт заказ в личку админам и напишет предупреждение в лог. |
| Бот не видит `/admin` | Ваш ID не в `ADMIN_IDS`. Узнать: `/id`. |
| Нет доступных дат | Все даты закрыты отсечкой, либо в ротации нет активного сета, либо у объекта не заданы дни доставки. |
| QR не генерируется | Не заданы `TELEGRAM_BOT_USERNAME` / `MAX_BOT_USERNAME`. |
| MAX молчит | Пустой `MAX_TOKEN`, либо выключен тумблер в `⚙️ Настройки → 📱 Каналы`. Ошибки авторизации видны в логе при старте. |
| Оплата не подтверждается | Проверьте ключи кнопкой `🧪 Проверить ЮKassa`; платёж должен быть в статусе `succeeded`. |
| Фото сета не показывается | Файл в `data/photos/` удалён — загрузите заново; бот в этом случае просто отправит текст. |

Логи пишутся в стандартный вывод — на bothost они видны в консоли приложения.
Уровень подробности — `LOG_LEVEL=DEBUG` в `.env`.
